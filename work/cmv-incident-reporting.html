Case study 02 · Enterprise architecture

Incident reporting across forms, APIs, and data

A responsive incident-reporting architecture designed for a planned rollout to 2,000+ employees across dealerships and workshops.

Organization
CMV Group
Role
Data Solutions Engineer
Period
Apr 2024 — Present
Planned scale
2,000+ employees

Operating context

Incident reporting crosses several user needs and data types. Employees need a responsive way to submit structured reports and attachments, while the organisation needs a controlled path for storage and administration across dealerships and workshops.

Architecture

I architected the platform around customised SharePoint and Plumsail forms with JavaScript behavior, Azure Functions as the API boundary, SQL Server for structured incident records, and Azure Blob Storage for attachments.

Designed around

  • Keep the employee-facing form responsive across the dealership and workshop environments in scope.
  • Separate the interface from persistence through Azure Functions rather than expose storage concerns to the client.
  • Use SQL Server for structured records and Blob Storage for attachments so each data type has an appropriate home.

Planned rollout

The architecture was prepared for a planned rollout to more than 2,000 employees, connecting capture, APIs, structured data, file storage, and controlled administration in one maintainable path.

Separate workflow I also automated employee share-statement generation, reducing a day-plus manual process to a batch workflow.
